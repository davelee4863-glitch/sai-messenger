AUTHORITY AND ATOMICITY
Workers Static Assets serves the original mvp/client bytes. A thin Worker gates local origins and delegates API/WS to a SQLite-backed Workspace Durable Object. This small private MVP uses ONE authority DO for all rooms, sessions, members, proposals, promises, RSVP, review histories and five-invite reservations. This avoids distributed approval/security transactions. It is not a design for unlimited users or room-per-object sharding.
Users and credential hashes remain authoritative in the DO. D1 holds a private, derived projection of user IDs/nicknames, invite counts and promise IDs/status/version (no message/appointment body, no credentials). D1 is never consulted to grant access, mark attendance, or confirm a promise. Every mutation and its projection outbox are committed by transactionSync in the same DO. D1 writes happen AFTER commit, sequentially; acknowledge exact epoch/revision/payload before deleting an outbox row. D1 errors/quotas leave durable outbox, and the API returns canonical DO data. Retry and binding-only rebuild are tested. Rebuild does not grant access.
Outbox flushes are bounded20 rows (<=41 D1 calls); pending metadata is visible only to the test operator. Activity triggers flush, and binding-only local maintenance can flush/rebuild explicitly. There is no autonomous retry alarm yet: after idle failures, the operator must trigger retry. Large backlogs require repeated bounded flushes. A D1 projection is dispensable and rebuilt from DO backup, so no distributed D1/DO snapshot pretending to be atomic.

BACKUP AND RESTORE
Binding-only maintenance exports a canonical JSON logical snapshot with SHA256 checksum after storage.sync. Backup contains private synthetic credential hashes and data; store offline, restrict permissions, do not include in evidence/source archives. Checksum detects accidental corruption, not a malicious operator who can recompute it; authenticate/encrypt transported archives before nonlocal use. Restore only into a new empty isolated DO namespace; schema/table columns/FKs checked in one transaction. Sessions, pending approval reviews, rate/usage state and outbox are discarded; epoch increments; canonical business data/invite usage retained; D1 projection is rebuilt. Never roll current user data back via a network endpoint.
Native DO PITR is documented30days, but unavailable in local development: NOT_RUN. D1 Time Travel Free7days: NOT_RUN. Cloud DB durability/backup retention and browser trusted HTTPS/WSS need approved remote verification. Local restart and independent logical backup restore do pass. Local HTTP is explicitly labelled synthetic/local and has HttpOnly/SameSiteStrict cookies; HTTPS-aware Secure cookie behavior is separately tested by dispatchFetch, not claimed as browser TLS/WSS trust.
